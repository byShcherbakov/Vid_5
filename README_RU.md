# Практическая работа 5. Вариант 22

**«Объектно-ориентированный подход к созданию графических сцен»**

Готовая программа на C++17 и Qt Widgets. Используются `QGraphicsScene`,
`QGraphicsView`, собственные классы графических объектов и рисование через
`QPainter`. Внешние картинки для арбуза и долек не используются.

## Запуск в Qt Creator

1. Распакуйте архив в отдельную папку.
2. В Qt Creator выберите **Файл → Открыть файл или проект**.
3. Откройте **CMakeLists.txt**.
4. Выберите установленный **Desktop-комплект Qt** и настройте проект.
5. Нажмите **Ctrl+R** или зелёный треугольник запуска.

Для macOS выбирайте комплект Qt для macOS. Для Windows нужен комплект MinGW
или MSVC с установленным соответствующим компилятором. Комплект Windows
MinGW не подходит для сборки на Mac. Для CMake-проекта нужен установленный CMake.

В архиве также есть `WatermelonScene.pro` для qmake. Его можно открыть в Qt
Creator вместо `CMakeLists.txt`, если удобнее использовать qmake.

Файлы этого проекта собираются **вместе с библиотеками Qt**. Команда
`g++ main.cpp` или кнопка Run Code для одного файла в VS Code не собирает
Qt-проект. Запускайте весь проект через Qt Creator или CMake.

Исходники рассчитаны на Qt 5.15 и Qt 6. Для обычной сборки нужен модуль
**Widgets**, для необязательных автоматических проверок также нужен **Test**.
Сборка и автоматические проверки выполнены на Linux с Qt 6.4.2 и GCC 13.3.
Сборки для Windows и macOS в архив не включены: проект нужно собрать
выбранным комплектом Qt на своём компьютере.

## Управление

| Действие | Результат |
|---|---|
| «+ Добавить арбуз» | Добавляет целые арбузы в случайных местах |
| «+ Кнопка «Выход»» | Добавляет кнопки «Выход» в случайных местах |
| Поле «Количество» | Задаёт число объектов за одно добавление |
| Зажатая ЛКМ и движение мыши | Перетаскивает объект |
| ПКМ по целому арбузу | Удаляет арбуз и создаёт ровно 8 отдельных долек |
| ПКМ по дольке | Удаляет именно эту дольку |
| Щелчок ЛКМ по кнопке «Выход» на сцене | Вызывает проверку закрытия окна |
| Крестик окна | Вызывает ту же проверку закрытия |
| «Очистить» | Удаляет кнопки, арбузы и дольки; оставляет счётчик |

Перемещать можно кнопки, целые арбузы, дольки и сам счётчик. Объекты
остаются внутри границ сцены. При перетаскивании кнопки «Выход» закрытие
не вызывается: программа различает щелчок и перемещение мыши.

Число объектов на сцене не ограничено значением 256. Поле количества
задаёт размер одной порции от 1 до 9999; добавления можно повторять.
При заполнении сцены объекты могут перекрываться. Захваченный объект
поднимается над другими обычными объектами, счётчик остаётся поверх них.

## Как считается число 256

Счётчик реализован как **отдельный графический объект**. Он включён в число
всех объектов сцены. Это правило прямо указано на его карточке.

```text
Всего = кнопки + целые арбузы + дольки + 1 счётчик
```

Каждый арбуз, каждая долька, каждая кнопка и счётчик представлены одним
`QGraphicsItem`. Полосы, семечки, тени и надписи рисуются внутри `paint()`;
дополнительных объектов сцены для них нет. Сетка фона тоже рисуется отдельно
и в подсчёт не входит. Панель управления находится вне сцены.

При запуске всего **3 объекта**: 1 арбуз, 1 кнопка и 1 счётчик.

При разрезании арбуза общее число меняется на **+7**, потому что 1 объект
удаляется и 8 добавляются. Удаление одной дольки меняет число на **−1**.

Закрытие разрешено только при равенстве `objectCount() == 256`.
При любом другом числе выводится точное сообщение **«Отсюда не сбежать!»**,
а окно остаётся открытым.

### Быстрая проверка условия выхода

Сразу после запуска, когда на сцене 3 объекта:

1. Установите количество **252** и добавьте кнопки — получится **255**.
2. Попробуйте закрыть окно — появится «Отсюда не сбежать!».
3. Установите количество **1**, добавьте кнопку — получится **256**.
4. Закройте окно крестиком или щёлкните ЛКМ по кнопке «Выход» на сцене.

Для отдельной проверки 257 объектов добавьте ещё один объект перед закрытием:
выход снова будет запрещён. Если нужно начать заново, нажмите «Очистить»:
останется 1 счётчик. После очистки для числа 256 нужно добавить **255** объектов.

### Объектно-ориентированный подход

`SceneObject` наследуется от `QGraphicsObject`, который объединяет
графический объект и механизм сигналов/слотов. Общий класс содержит
перетаскивание, ограничение перемещения границами сцены, обработку наведения
и различение щелчка и перетаскивания.

От него наследуются четыре класса:

- `ExitButtonItem` рисует кнопку и при щелчке испускает `exitRequested()`.
- `WatermelonItem` рисует целый арбуз и при ПКМ испускает `cutRequested(this)`.
- `WatermelonSliceItem` рисует дольку и при ПКМ испускает `removeRequested(this)`.
- `CounterItem` рисует карточку со счётчиком и числом объектов каждого типа.

В каждом классе реализованы `boundingRect()`, `shape()` и `paint()`.
`boundingRect()` задаёт прямоугольник перерисовки, `shape()` — область
попадания мыши, а `paint()` — само изображение. У арбуза область попадания
овальная, у дольки она повторяет контур дольки.

`WatermelonScene` получает сигналы объектов и изменяет сцену. При ПКМ
объект сразу убирается со сцены через `removeItem()`, затем освобождается
через `deleteLater()`, чтобы не уничтожать его посреди собственного
обработчика события. Счётчик обновляется после завершения операции.

`MainWindow::closeEvent()` содержит единственное правило закрытия:

```cpp
if (scene_->objectCount() == 256) {
    event->accept();
    return;
}
event->ignore();
QMessageBox::information(this, QStringLiteral("Выход запрещён"),
                         QStringLiteral("Отсюда не сбежать!"));
```

Кнопки на сцене вызывают `MainWindow::close()`. Поэтому кнопка и крестик
окна проходят одну и ту же проверку в `closeEvent()`.

## Сборка из терминала

Если Qt установлен не в стандартный путь, передайте путь к выбранному
комплекту Qt в `CMAKE_PREFIX_PATH`.

Пример для macOS с Qt из Homebrew:

```bash
cmake -S . -B build -DCMAKE_PREFIX_PATH="$(brew --prefix qt)"
cmake --build build --parallel 2
open build/WatermelonScene.app
```

Или выполните `bash run-macos.sh`. Можно явно передать путь к Qt:

```bash
QT_PREFIX="$HOME/Qt/6.8.3/macos" bash run-macos.sh
```

Версия в этом примере — только пример пути; укажите свой установленный комплект.

Пример для Windows из среды с доступным CMake и MinGW:

```powershell
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_PREFIX_PATH="C:/Qt/6.8.3/mingw_64"
cmake --build build --parallel 2
.\build\WatermelonScene.exe
```

Путь к Qt замените своим. `g++` и `mingw32-make` должны быть из соответствующего
MinGW-комплекта, а каталог `bin` выбранного Qt должен быть доступен при запуске.
В Qt Creator это настраивается выбранным Desktop-комплектом.

Linux:

```bash
cmake -S . -B build
cmake --build build --parallel 2
./build/WatermelonScene
```

## Автоматические проверки

```bash
cmake -S . -B build-tests -DBUILD_LAB_TESTS=ON
cmake --build build-tests --parallel 2
ctest --test-dir build-tests --output-on-failure
```

Если Qt установлен не в стандартный путь, добавьте `-DCMAKE_PREFIX_PATH=...`.
Тесты работают через offscreen-платформу Qt без отдельного рабочего стола.
Проверяются количество и типы объектов, пакетное добавление через панель,
реальные события мыши для разрезания и удаления, перетаскивание всех четырёх
типов, отсутствие закрытия при перетаскивании кнопки, границы сцены,
закрытие при 255/256/257 объектах и многократное создание/удаление.
